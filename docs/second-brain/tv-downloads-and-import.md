## Approved behavior

| Decision | Rule and reason | Authority |
| --- | --- | --- |
| Manual review and one-shot bulk | The expanded-series download controls open release review. Explicit submission queues the selected releases. Bulk Download searches once for released missing episodes and reports unavailable sources. This keeps a one-off download separate from persistent Follow and its source-retry schedule. | [Manual review decision](../tv-contracts.md#tv-change-02-clear-activation-and-downloads-across-seasons) · [Bulk and Follow boundary](../tv-contracts.md#tv-change-04-new-release-following-versus-downloading-an-existing-series) |
| Choose and preserve the destination | Continue an established show home and its season naming convention. Ambiguity or a destination that fails ownership or path checks requires review. A genuinely new collection can reserve a home derived from the saved canonical title and first-air year at Download or Start. The directories are created when verified files are ready to publish. This keeps existing collections stable and avoids empty folders from preview or submission. | [Existing storage rules](../tv-contracts.md#existing-storage-contracts) · [Approved new-home handoff](../tv-contracts.md#implementation-handoff-decision-2026-10-08) |
| New jobs and older jobs | Dante approved the normal CP lifecycle for new TV jobs on 2026-10-05. Download to staging, verify the episode files, publish them under the approved show and season, and record the episode bindings before removing the torrent and its staged copies. New normal jobs have no seeding phase. Older jobs retain their recorded import and seeding policy. | [Normal lifecycle decision](../plans/2026-10-05-tv-download-storage-cp-normal-behavior.md#contracts-affected-and-contract-change-decision) |
| Protect existing media | A matching destination file can be reused when the bytes and episode binding are compatible. A conflicting ordinary import requires review. A verified, explicit Upgrade can add a separate version while preserving the existing copy. | [Collision and upgrade contract](../plans/2026-10-05-tv-download-storage-cp-normal-behavior.md#exact-behavior-contract) |
| Partial import and recovery | A pack can publish its verified episodes while reporting the failed files and retaining recovery sources. For a cleanup failure after publication, recovery uses the committed files and bindings and retries cleanup. Rollback for normal jobs requires intact sources and stops being available when cleanup starts. | [Completion and recovery contract](../plans/2026-10-05-tv-download-storage-cp-normal-behavior.md#exact-behavior-contract) |
| Auxiliary files | Clearly identified samples, trailers, extras, and featurettes in a package do not count toward episode coverage. Verified cleanup can remove recorded job-owned auxiliary copies after publication. Shared, changed, or unknown files remain protected. | [Season-pack auxiliary file decision](../plans/2026-10-10-tv-pack-auxiliary-files-fix.md#exact-behavior-contract) |

## How to interpret the result

A finished transfer is evidence that the payload arrived. For a downloaded episode to appear as available, CP needs a catalog binding to a file that still exists. If verification fails before publication, the affected episode has no new available version. If a pack imports partially, check each episode separately. If cleanup fails after publication, check the committed binding and destination before treating the episode as missing. [Downloads and Library diagnosis](../atlas/tv-downloads-and-import.md#finished-transfer-missing-episode)

TV Downloads reads acquisition and transfer state, while the Library reads catalog bindings and checks files. [Source map](../atlas/tv-downloads-and-import.md)

The later contract and season-pack reports cover destination, batch, and partial/recovery checks with their own limits. These results describe the reported runs.
