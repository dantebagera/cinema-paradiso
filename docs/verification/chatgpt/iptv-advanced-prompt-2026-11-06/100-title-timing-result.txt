Metric boundaries: Timed from request invocation through completed streamed response. Includes transport/network and token access inside the request. Does not include initial data preparation, pre-request authentication, CP's initial matching, TMDB searching/verification, catalogue application, or production scheduler contention. No TMDB calls were made. These numbers measure prompt overhead on CP's normal batch size; they do not establish full CP workflow duration or a universal live request average.

Accuracy scope: JSON schema and source ID coverage were checked. Movie identity correctness and downstream match yield were not re-evaluated in this timing-only experiment. The prior 48-title experiment includes a limited candidate-retrieval comparison.

Interpretation: The proposed concise advanced rules added little request latency in these four measurements. Their input overhead is 240 tokens shared across the batch; total usage rose about 5%. Two runs per prompt on one sample are insufficient for a general latency guarantee. Full CP end-to-end timing and production acceptance remain separate work.

Evidence: experiment.json contains both exact prompts and the 100 inputs; calls.json contains request metrics and provider-reported usage; trial*.json contain complete responses; summary.json contains recalculated means and differences.
