Add optional JSON `criteria` generated by `tvListCriteria`: version 1, media type TV, discover scope, simple mode/catalog feed, genre/country/rating/minimum-votes/year groups and allowed sort. Parse within the existing route action/error boundary. Validate with current `TVSearch.normalize(criteria, 'discover')`; apply `matches` and `sort_rows` in the read owner after membership/query/status and before total/page calculations. Do not copy predicates into JSX or a second backend rule.

- Omitted criteria preserves current alphabetic/default results. Empty criteria with auto sort also preserves that ordering. Existing page-size default 40/cap 100 and response fields `lists`, `items`, `total`, `page`, `page_size`, `total_pages` remain.
- Use current search fields: first-air-date for year/date, normalized genre IDs/names, origin country, rating/votes/popularity. Missing values fail an active corresponding constraint; they are not invented zeros or dates. Sort accepts current normalized keys/directions only; use existing behavior for auto/provider order.
- Example: a list has 65 shows, three comedies satisfy the rating threshold, two reside beyond the original first page. The response must contain all three matches on page one, `total=3`, `total_pages=1`; filtering just the loaded forty is incorrect.
- Invalid JSON/type/media/scope/group/sort yields current action's 400; missing resources retain 404; operational read failure retains 503. An invalid request must not return an apparently unfiltered success. This is a read operation: no membership, curation, task or persistence writes, and no new retry/concurrency protocol.
