## Problem and decision

- **What happens now:** `services/tv_acquisition.py:346` uses the first TV root plus the TMDB number and maps every non-copy profile to hardlink/copy. `services/verified_import.py` publishes each basename there and always retains its source. TV cleanup removes the torrent without removing staged media. Its initial collision planner renames occupied targets rather than distinguishing identical content from conflicts.
- **User impact:** A season is split across directories and completed downloads occupy staging and library storage. Current South Park bindings put S27E01–E02 under `G:\TV\South Park\Season 27` and E03–E05 under `G:\TV\2190`. Both show paths are approved. Existing TV jobs for South Park, Dark Matter, and Slow Horses use hardlink/copy, with retained copies.
- **What Dante wants:** Correct existing show/season placement and normal move/cleanup for new TV downloads. Keep filenames, episode identity, selected-file validation, quality verification, per-episode claims, and duplicate-submission protections.
- **Confirmed:** Destination construction and retention are current source behavior; the split paths are in the current read-only TV database. The movie reference moves release payloads without standardizing names and distinguishes identical data, conflicting data, and explicit upgrades.
- **Planning checkpoint:** A green current baseline had not yet been established by the planning chat. The execution ledger now records current checks; production processes still cannot be assumed to have loaded source edits.
- **Open decisions / bounded exclusions:** New-show naming and arbitrary import homes are not decided. A series without an approved, resolvable home must show a destination-required result and cannot submit. No title/ID folder fallback. Existing nonstandard layouts whose season placement cannot be proved require review. These exclusions do not block implementing resolved existing collections. Present this limitation in the implementation report.
- **Scope:** New manual episode/selection/season downloads, new acquisitions generated by bulk/Follow tasks, destination preview/selection, truthful desktop lifecycle/status text, recovery, and regression coverage. Existing acquisition jobs retain their stored destination/lifecycle. No release-ranking changes, extra seeding feature, library reorganization, live downloads/deletions/migrations, restarts, commits, pushes, packaging, or deployment.

### Backend, if affected

**1. Destination owner.** Add `TVCatalogRepository.resolve_import_destination(series_id, season, roots)` returning the destination shape above, and `set_import_home(series_id, path, roots)` for an explicit approved-home choice. Add `tv_import_homes(series_id PRIMARY KEY REFERENCES series(id), path REFERENCES tv_path_assignments(path))` to the existing TV schema: one preferred selection referencing existing approved ownership, not a separate folder map. Bump TV schema to 5 and preserve restore support for version 4; test transactional upgrade/restore in disposable databases. No live migration during implementation.

Resolve a recorded valid preference first. Otherwise use the unique approved whole-show home proved by episode bindings in recognized season subdirectories. A flat downloaded-release folder is not a competing whole-show home merely because it is approved. This structural distinction, not title matching or a special numeric-folder blacklist, resolves South Park to its established season hierarchy. If multiple credible whole-show homes remain, return `needs_choice`; if no approved home can be proved, return `needs_home`. Do not choose by first-root order, title resemblance, approval date, or hardcoded show/ID.

Reuse an existing uniquely associated requested-season directory. For a new regular season, derive its name from the selected home's one consistent established naming convention (e.g. `Season 01`→`Season 28`); create it only when verified files are ready. Ambiguous naming or specials without a proved destination require review. Paths must remain inside configured TV roots, outside exclusions/staging, and not be assigned to another series. Preview is read-only; persist an inferred unique preferred home only during authorized submission, or during an explicit UI home selection. Add `POST /api/tv/series/<series_id>/import-home` with body `{path}` calling this owner; invalid choices return the existing route error envelope with no queue changes.

**2. New job contract.** `TVAcquisition` is the sole composer of the approved normal TV lifecycle: all newly created manual/bulk/Follow intents use `tv_lifecycle_version:1`, `import_mode:'move'`, `seeding_policy:{seeding_mode:'none'}`, and a snapshotted resolved destination/home/season. Existing quality profiles continue to control source eligibility/ranking unchanged; do not rewrite shared profiles, the movie default, or profile versions just to change TV storage. New seeding configuration is outside this “for now” scope. Jobs without this lifecycle marker keep their stored modes/policies and old journal semantics. This is persisted-job compatibility, not a runtime feature flag; retire its execution branch only after all nonterminal old jobs are resolved, retaining historical status decoding.

Validate destination before creating an intent/claim or calling qBittorrent. Revalidate before file publication against current roots, assignments and exclusions. A changed/invalid snapshotted destination pauses for review; never silently retarget an existing transfer. Batches and Follow use the same owner and return actionable destination failures without submitting blocked targets. Request keys remain idempotent; a retry reuses its recorded destination and never changes ownership underneath another job.

**3. File publication and move recovery.** Extend `import_verified_files` in the existing owner to accept `mode='move'`, with an explicit `upgrade=False` argument. Keep the same journal authoritative; use existing hash/exclusive temporary publication and record source→target, measured facts, episode mapping, method, and cleanup progress. A cross-volume move may copy during verified publication but may not leave its source after successful final cleanup. Keep originals intact until every selected video is published and `TVCatalogRepository.bind_files` commits the exact destinations atomically. Before cleanup, record durable TV-publication success and enough facts to recover from destination files when sources are subsequently gone. Never re-probe a deleted source or recreate staging on restart.

For an existing target, byte-identical content reuses that target only if its TV binding is absent or compatible with the selected episodes; a conflicting binding requires review. Different bytes block a normal import without changing either file. Explicit verified upgrades keep old versions and reserve deterministic numbered sibling paths. Record a reused target as pre-existing so rollback never deletes it. Hold the existing completion lock, reserve target names in the journal, and use exclusive publication against concurrent imports.

**4. Completion and cleanup.** Add a completion method in `TVAcquisition` for lifecycle-version-1 jobs and an existing-owner helper `finalize_verified_move(jobs, torrent_hash, staging_root)` in `services/verified_import.py`. Sequence: selected-file verification → destination publication → TV binding commit → stop/remove only this torrent without deleting destination files → verified staging cleanup → final imported state with `source_retained:false`, `library_scan_pending:false`, `identity_handoff.state:'tv_published'`, `rollback_available:false`. Verify committed bindings and destination size/hash before source deletion. Removal failure is `cleanup_failed`; retry cleanup only, never recopy/rebind. Existing `retry` operation may retry cleanup failures under the existing retry policy without deleting a blocklisted/changed source.

Cleanup can unlink only sources named by this job's validated manifest and journal beneath its recorded staging directory, whose fingerprints still match, and which are not referenced by another active job. Remove empty job subdirectories only; never recursively delete staging, arbitrary neighbors, the library, or pre-existing unknown files. Unknown contents/shared references pause cleanup with a clear reason. Source already missing after a journaled cleanup checkpoint is resumable if the committed destination still matches. Partial imports or failed media checks retain source data, report precise successes/failures, and do not claim completed move/cleanup. This is a recovery exception, not successful retention.

Before cleanup starts, normal-job rollback may remove only journal-created destination files and unpublish only this job's bindings, preserving intact sources and pre-existing reused targets. Serialize it against completion. After cleanup starts, reject retained-source rollback before mutation; finishing recovery is the supported path. Preserve cancel-and-retain semantics and all legacy rollback/seeding tests using genuine legacy records. No existing imported files, jobs, or bindings are relocated by this implementation.

**Example:** A new South Park S27E03 download previews the established `South Park\Season 27`, not `2190`; its verified video appears there, the TV catalog points there, the torrent is removed, and its staged video disappears. Current misplaced E03–E05 are not repaired by this source change.
