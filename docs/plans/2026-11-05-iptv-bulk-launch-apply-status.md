**Status:** Approved for source implementation in the current checkout and isolated verification on November 5, 2026. Dante requested a new implementation task after reviewing this plan. Approval includes a single explicit confirmation for all eligible verified Film matches in the saved job, across every page, with proposal review optional. ## Problem and decision

- **What happens now.** The Start form asks for a maximum number of ChatGPT requests, while CP fixes the first-pass batch size at up to 100 titles. The distinction between 100 calls and 100 titles per call was unclear. In the 6,413-source run, 12 of 100 was the request counter while 1,148 was the saved source count.
- **What happens after matching.** The review panel pages through 20 outcomes at a time and only submits selected IDs from the visible page. At the observed checkpoint, Apply saved 20 matches and left 696 verified proposals awaiting Apply. Applied matches remained on the same page under “20 verified on this page,” even when that page had zero left to apply. This workflow scales with the number of pages.
- **What happens during a status freeze.** The browser showed “Failed to fetch” and froze at 3,139 of 6,413 with “Connecting to ChatGPT.” Two live read-only checks advanced from 3,579 to 3,586 in eight seconds. The earlier “Pausing at the next checkpoint” screen also lagged a backend that had recorded a pause. In `useAIJob.js`, the success path schedules the next read and the error path exits. The cause of the individual failed status request and the reason for any slowdown before the first Pause are unknown.
- **Why the page feels crowded and slow.** Each catalog queue reuses most of the same dashboard, including the bulk job. A tab change clears the grid and waits for the review response, facets, worker status and settings in the same `Promise.all`. The live review endpoints returned distinct counts and took about 1.7–3.6 seconds during read-only probes. The page also mixes matching with credentials and maintenance. Settings already has an IPTV Providers section, plus separate general TMDB and Ollama controls. IPTV’s values are stored separately through `IPTVMetadataSettings`.
- **What Dante wants.** Choose titles per request. Let CP calculate the request estimate. Keep one explicit action to apply the job’s verified matches without reviewing them page by page. Remove applied rows from pending review and recover from status read failures without restarting the scan.
- **Open decision.** A separate option to select every provider source remains outside the approved scope. Launch uses the selection from Catalog review. Dante approved 100 titles as the default, Start as approval of the calculated first-pass ceiling, separate explicit approval for extra calls, and explicit confirmation before catalog writes.
- **Scope.** Desktop IPTV Metadata, the bulk job and its provider-local match writer, and the destinations in Settings and Maintenance for controls moved out of Metadata. Preserve legacy IPTV paths, Movie, TV, Ollama, the 24-call Continue rule on legacy AI jobs, existing verification thresholds, and the explicit Play lookup. Changes to the live job, credentials, production bundle, or catalog are outside plan authoring.
