## Storage, upgrades and measured facts

| Entry point | Path and owner |
| --- | --- |
| Maintenance → Storage | `CleanupWorkspace.loadMaintenanceSection` calls `GET /api/maintenance/audit?section=storage` with page and optional search text. `_maintenance_audit_from_catalog` caches by media generation and reads `CatalogStore.maintenance_candidates` plus stored identity fingerprints. `build_maintenance_audit` computes the full catalog projection. `_maintenance_workspace_payload` searches and pages the resulting groups. `DuplicatesCleanupTab` shows exact files, reasons and evidence and can play any copy through the local player. [Workspace](../../src/features/cleanup/CleanupWorkspace.jsx) · [Route and cache](../../app.py) · [Catalog store](../../services/catalog_store.py) · [Audit](../../services/maintenance_audit.py) · [Playback](playback-and-streaming.md) |
| Duplicate verdicts | `_duplicate_groups` groups possible copies by identity and evaluates pairs. A recommended removal requires accepted identity with a shared public ID and safe comparison evidence, with a separately checked case for a short, explicitly named sample next to its full movie. Read the row's content, technical-quality and storage evidence. Identity conflicts and uncertain comparisons remain for review. File size measures potential space, and frame rate can support content equivalence. Neither establishes technical superiority. The current projection covers measured video, runtime, framing and audio, with subtitles excluded. [Comparison owner](../../services/maintenance_audit.py) |
| Upgrade candidates | The **Upgrade candidates** stat opens Movie Library via `App.openCleanupTab` with the `upgrade` filter. `build_maintenance_audit` includes accepted, verified files ranked below 1080p, unless their duplicate group already has a file ranked at least 1080p. `_maintenance_upgrade_path_keys` feeds both the card annotation and SQL filtering/selection. The API also exposes `section=upgrades`. A candidate is a library assessment. Starting a source search or download goes through Movie acquisition. [Navigation](../../src/App.jsx) · [Library](../../src/features/library/LibraryWorkspace.jsx) · [Audit](../../services/maintenance_audit.py) · [Read and selection](../../services/catalog_store.py) · [Acquisition map](movie-downloads-and-import.md) |
| Measured quality | `probe_media_file` uses MediaInfo to select streams, verify the file did not change during the probe, and produce a complete fact record. `classify_dimensions` owns the derived class. SQLite stores the exact dimensions, filename claim, derived class, source, conflict and probe status. `resolution` is a compatibility field for the class. `_metadata_file_facts` calls the probe during ingestion and path migration. `run_file_facts_backfill` processes eligible older records in bounded batches. The audit reads stored facts. File View and reconciliation check physical state through their own reads. [Probe](../../services/media_file_facts.py) · [Backfill](../../services/media_file_backfill.py) · [App wiring](../../app.py) · [Store](../../services/catalog_store.py) |

## File actions and record propagation

| Action | Execution and failure path |
| --- | --- |
| Rename one file | Movie Library and Maintenance Identity call `POST /api/rename-file`. `rename_file` checks the configured Movie root and source, builds a title/year filename with the existing extension and quality/source tags, strips invalid filename characters and rejects a destination collision. After the filesystem rename, it calls `_migrate_library_path` and requests a best-effort Plex rescan. UI updates the row with the returned path. [Library action](../../src/features/library/LibraryWorkspace.jsx) · [Maintenance action](../../src/features/cleanup/CleanupWorkspace.jsx) · [Route](../../app.py) |
| Smart Rename | `IdentityReviewPanel` and `SmartMatchPanel` use `/api/metadata/smart-rename/preview` and `/apply`. Preview stores one token and proposed destinations, flagging invalid or conflicting paths. Apply requires the current token and selected paths, rechecks root, file and collision conditions, migrates successful renames through the same path helper and reports failures per file. The preview document is `smart_rename_preview.json` under the metadata store. [Identity Review](../../src/components/IdentityReviewPanel.jsx) · [Smart Match](../../src/components/SmartMatchPanel.jsx) · [Routes](../../app.py) |
| Fix Path | Maintenance Identity offers this for a nested unmatched file. `POST /api/fix-path` rejects Plex-matched files and files already at the permitted depth. It moves a file upward, or moves its folder when the folder looks like a movie title with year and contains one recognized video at that level. The route separately validates the destination for each branch and rejects collisions. It then uses the shared migration helper and asks Plex to rescan. If the UI shows the action but it fails, check the actual path depth and the two destination calculations. [UI and confirmation](../../src/features/cleanup/CleanupWorkspace.jsx) · [Move route](../../app.py) · [Root boundary test](../../tests/test_catalog_file_mutations.py) |
| Maintenance delete | `CleanupWorkspace.requestDelete` posts selected paths to `/api/delete` with `preview`. The `LibraryMutationService` resolves files within the Movie roots and can propose a complete first-level folder only when every video is selected and the folder contains recognized sidecars or selected videos. Symlinks and unknown file types prevent the folder action. Execution replans against current files and only considers whole folders explicitly returned by the UI as allowed targets. It rechecks the current audit's audio-language loss and returns 409 unless the submitted path/language acknowledgements match. Successful paths and per-target failures are reported separately. [Preview and confirmation](../../src/features/cleanup/CleanupWorkspace.jsx) · [API](../../app.py) · [Filesystem owner](../../services/library_mutations.py) |
| Movie Library delete | `LibraryWorkspace.confirmDelete` calls the same route once per path with `trash: true`. This path moves each selected file to the Recycle Bin. It reports a failure if the server requires an audio-language acknowledgement. The acknowledgement UI is in Maintenance. Storage's keep-one-copy check belongs to the duplicate selection UI. The generic deletion route has its own root, file and acknowledgement checks. [Library action](../../src/features/library/LibraryWorkspace.jsx) · [Maintenance controls](../../src/features/cleanup/CleanupWorkspace.jsx) · [Route](../../app.py) |

- **After rename or move** · `_migrate_library_path` probes the destination through `AppMetadataStore.migrate_path_records`, marks identity evidence changed, and refreshes path and filename caches. `CatalogRepository.migrate_path_records` moves file, Plex, manual match and identity fingerprint records and updates conflict and inventory records. It rebuilds canonical projections, migrates the playback history path, rebinds the movie key and advances generation for changed documents. App metadata also rewrites migration and identity-audit path lists. [App and metadata store](../../app.py) · [Repository transaction](../../services/catalog_repository.py)
- **After delete** · `LibraryMutationService._execute_action` moves the target to the Recycle Bin by default, then removes its path records. `CatalogRepository.remove_path_records` removes the selected file's playback history and path-bound records, rebuilds canonical state and updates generation. `app.py` evicts caches and publishes a catalog event, and the initiating UI removes successful paths and announces a library change. Catalog record changes follow each successful filesystem action, so a batch can partly succeed. [Filesystem owner](../../services/library_mutations.py) · [Repository](../../services/catalog_repository.py) · [Event and cache wiring](../../app.py) · [Browser event](../../src/api/library.js)
- **Restore or external path change** · Windows Recycle Bin is the file recovery mechanism for the default delete flow. The traced Movie delete path exposes no CP restore action or retained path-history record. If a file is restored outside CP, observer/startup catch-up or explicit reconcile can detect it. A restored file needs a normal catalog entry, and playback history removed by deletion has no automatic recovery in this path. The observer can enqueue both old and new paths for external moves, while the explicit CP rename/move helper is what migrates path-bound records. Reconciliation scopes pruning to available roots or directories. If a disk operation succeeded but its record update failed, inspect both paths and the stored rows before retrying. [Observer](../../services/library_observer.py) · [Ingestion and reconciliation](../../services/library_ingestion.py) · [Startup and offline-root contract](../plans/online-library-ingestion-final-card-zero-regression-plan.md#48-startup-catch-up)

## Where to start with a report

| Symptom | First evidence and tests |
| --- | --- |
| A duplicate is missing, incorrectly recommended, or carries an audio warning | Compare accepted public IDs, stored probe evidence and each file's decision blockers/warnings. Start with `test_conflicting_strong_ids_never_become_a_duplicate_group`, `test_multi_file_group_uses_pairwise_dominance_instead_of_one_reference`, and `test_delete_preview_and_execution_require_audio_language_loss_acknowledgement`. [Verdicts](../../tests/test_maintenance_audit.py) · [Delete API](../../tests/test_maintenance_audit_api.py) |
| A low-quality file is missing from Upgrade candidates | Compare the measured/fallback class, accepted identity and other copies in the same group. Check `test_projects_storage_upgrades_and_identity_from_one_catalog_snapshot` and `test_low_measurement_is_not_promoted_by_1080_filename`. [Audit](../../tests/test_maintenance_audit.py) · [Probe](../../tests/test_media_file_facts.py) |
| File View or Maintenance still shows older facts | Check the stored size/mtime fingerprint, probe status, generation and backfill status. `test_reconcile_refreshes_changed_facts_without_rematching_accepted_identity` and `test_bounded_batches_resume_and_second_pass_is_idempotent` cover different updates. [Reconciliation](../../tests/test_catalog_file_mutations.py) · [Backfill](../../tests/test_media_file_backfill.py) |
| Delete preview would include a folder, or a file remains after a batch | Compare the confirmed folder list with the files and sidecars still present and the per-target result. Check `test_cleanup_never_expands_file_deletion_without_confirmed_folder_target` and `test_delete_does_not_update_catalog_when_trash_fails`. [Mutation tests](../../tests/test_library_mutations_service.py) · [Dialog summary](../../tests/deletionPlan.test.mjs) |
| Rename, move, restore or delete leaves a stale card or unexpected progress | Confirm both disk paths, then catalog and path history. Check `test_rename_and_delete_refresh_catalog_without_rescan`, `test_rename_migrates_progress_through_repository_owner`, `test_remove_path_deletes_only_that_file_progress`, and `test_bounded_directory_reconciliation_prunes_deleted_file_only_in_scope`. [File mutations](../../tests/test_catalog_file_mutations.py) · [Playback history](../../tests/test_playback_history_mutations.py) · [Directory reconciliation](../../tests/test_library_ingestion_paths.py) |
