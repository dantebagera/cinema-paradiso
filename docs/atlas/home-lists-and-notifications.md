## Home

| Surface | Path and owner |
| --- | --- |
| Trending and Coming soon | `App.jsx::loadHomeTrending` and `loadHomeUpcoming` call `/api/tmdb/discover` independently. `currentHomeOwnership` checks catalog readiness and rejects stale ownership. `buildUpcomingHomeMovies` excludes effective Trending, deduplicates, chooses up to 20 in provider order, then sorts the preview. `HomeWorkspace` renders the shared rails and inline details. View all opens Discover Upcoming. [App](../../src/App.jsx) · [Preview helper](../../src/utils/homeMovies.js) · [Home](../../src/features/home/HomeWorkspace.jsx) · [Discover](search-and-discover.md) |
| New trailers | `App.jsx::loadHomeTrailers` calls `fetchHomeTrailers` → `GET /api/home/trailers` → `YouTubeService.get_home_trailers`. The service owns fixed sources, API pages, XML fallback, source-page cache, and per-source cursors. `HomeTrailersPanel` and `homeTrailerModel.js` own presentation and grouping, including alternate versions and channel selection. App opens the chosen video in `TrailerModal`. [App](../../src/App.jsx) · [Client](../../src/api/homeTrailers.js) · [Route](../../app.py) · [YouTube owner](../../services/youtube_playlist.py) · [Panel](../../src/features/home/HomeTrailersPanel.jsx) · [Grouping model](../../src/features/home/homeTrailerModel.js) |
| Continue Watching | `App.jsx::loadContinueWatching` combines `GET /api/player/continue-watching` with `GET /api/tv/continue-watching` when TV is enabled. Movie playback history and TV progress have separate owners. `ContinueWatchingRail` renders both with Resume, Restart, and Remove, and offers View card on Movie entries. [App](../../src/App.jsx) · [Home](../../src/features/home/HomeWorkspace.jsx) · [Movie route](../../services/player_routes.py) · [TV route](../../services/tv_routes.py) |
| Library health | `refreshHealthStats` reads `GET /api/stats` from `library_stats`. The Home `HealthPanel` renders the returned counts, stale/error state, and links to Library or Cleanup. The stats endpoint derives its counts from the Movie catalog and maintenance projections. [App](../../src/App.jsx) · [Stats route](../../app.py) · [Home](../../src/features/home/HomeWorkspace.jsx) |
| Following | `ReleasePanel` displays the Movie availability watchlist, with a full scan and explicit source review. Catalog reconciliation can remove an owned movie while provider work is pending. [Home](../../src/features/home/HomeWorkspace.jsx) · [Follow map](movie-follow.md) |

App retains loaded feeds and joins active operations when Home is hidden and reopened. On actual unmount, the lifecycle epoch protects publication. Trending uses saved suggestions on failure or empty results. Upcoming can continue through duplicate-heavy logical pages. An unfinished scan and an exhausted provider take different paths. Trailers can retain a stale feed and retry without losing selected source or pending append state. [App lifecycle](../../src/App.jsx) · [Home panel](../../src/features/home/HomeTrailersPanel.jsx)

## Lists and notifications

| Surface | Path and owner |
| --- | --- |
| Movie Lists | `ListsWorkspace` selects the Movie workspace, which loads `GET /api/user/lists` through `fetchUserListsCached`. `register_curation_routes` serves custom list CRUD, individual and bulk membership, and Watched/Watchlist toggles. `UserCurationStore` persists the `user_lists.json` document through the Movie SQL catalog and export. Reads project the accepted Library identity. Watched requires a committed owned movie; Watchlist accepts unowned movies. [List switch](../../src/features/movie-lists/ListsWorkspace.jsx) · [Movie workspace](../../src/features/movie-lists/MovieListsWorkspace.jsx) · [Routes](../../services/curation_routes.py) · [Store](../../services/curation_store.py) |
| Movie list display and filters | `MovieListsWorkspace` resolves ownership through `/api/library/check` and hydrates fields through `/api/tmdb/card-projections`. `useListCatalogFilters` and its helper filter and sort the membership before paging. When required projection data fails, the workspace shows incomplete refinement and retry. Discover, Library, and Home also use Movie curation routes. `observeCurationGeneration` and the shared list cache help refresh mounted callers. [Workspace](../../src/features/movie-lists/MovieListsWorkspace.jsx) · [Filter hook](../../src/hooks/useListCatalogFilters.js) · [Filter model](../../src/utils/listCatalogFilters.js) · [Curation client](../../src/api/curation.js) |
| TV Lists | `TVListsWorkspace` reads `GET /api/tv/lists`; `TVReadModel.tv_lists` applies list membership, title and typed criteria, sorting, and pagination. TV list CRUD and membership routes use `TVCatalogRepository`. Series Watchlist and Watched have separate series routes. Membership and progress use `tv-catalog.sqlite`. [TV workspace](../../src/features/movie-lists/TVListsWorkspace.jsx) · [Routes](../../services/tv_routes.py) · [Read model](../../services/tv_read_model.py) · [Repository](../../services/tv_catalog_repository.py) · [TV service composition](../../services/tv_services.py) |
| Sidebar notification history | `Sidebar` mounts `NotificationWindow`. The window polls `GET /api/notifications` for the global unread count and filtered history, and posts IDs to `/api/notifications/read`. `AcquisitionRepository.notifications` queries `notification_events` in the configured `acquisition.sqlite`. `mark_notifications_read` keeps the first read timestamp. `TVMonitoring` writes task lifecycle and review events through `notify` with stable event keys. [Sidebar](../../src/components/Sidebar.jsx) · [Notification window](../../src/features/notifications/NotificationWindow.jsx) · [Routes](../../services/tv_routes.py) · [Acquisition store](../../services/acquisition_store.py) · [TV Follow](tv-follow.md) |
| App toast | `App.jsx::notify` publishes transient UI messages. Movie Follow availability uses this owner and a release alert sound. Inspect Follow scan generations separately from notification read IDs. [App](../../src/App.jsx) · [Follow map](movie-follow.md) |
