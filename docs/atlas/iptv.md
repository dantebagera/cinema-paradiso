## 2026-11-13 IPTV integration candidate

`IPTVMovieStore.lookup_availability` and `lookup_sources` open existing schema-3/4 movie databases with `mode=ro`, without constructor, migration, projection or online calls. `IPTVProviderManager.movie_availability` reads the registry directly and uses four shared workers. `/api/iptv/movies/availability` accepts up to 100 distinct movie IDs; `/api/iptv/movies/sources` resolves a current accepted Film identity to exact raw sources. `ACCEPTED_FILM_SQL` is shared with CP grouping, and the query starts from `idx_source_matches_tmdb`. Missing/unsupported/failed catalogs return unknown, not absent. Schema 1/2 lack the required classification rule.

`IPTVWorkspace` owns provider-local portrait filters, navigation snapshots and Back; the small Filmography button instead uses `App.openPersonInDiscover` with `fullFilmography: true`; `IPTVPeopleCredits` reuses `PersonCreditCard` and `HorizontalCardRail`. The existing movie query filters `movie_credits` before paging. `/people/<person_id>` uses `IPTVTMDBClient.person`, with shared normalization in `tmdb_people.py`. Session ownership moved to `useIPTVPlaybackSession`/`iptvPlaybackSession`; both the workspace and Movie stream dialog share it. `IPTVSourceList` owns source-version rows. Tests: `test_iptv_movie_availability.py`, `test_iptv_people.py`, `iptv_playback_session.test.mjs`, `e2e/iptv-people.spec.js`.

## Provider state and playback

- `IPTVProviderManager` owns `<user_data>/iptv/providers.json`, including the remembered provider. It validates provider paths, creates one service and one movie service per provider, and owns legacy migration and provider removal. The legacy migration backs up and validates the original catalog before installing the provider-scoped layout. Provider removal checks the exact name. Each `iptv/providers/<provider_id>/` root has `provider.json`, raw `iptv.sqlite`, image and playback directories, and the separate movie projection `movies.sqlite`. Metadata configuration is shared among IPTV providers at `iptv/metadata-settings.json`. [Manager](../../services/iptv_provider_manager.py) · [Raw store](../../services/iptv_store.py) · [Movie store](../../services/iptv_movie_store.py) · [IPTV settings](../../services/iptv_metadata_settings.py)
- `IPTVService._sync_worker` pulls Xtream categories and items and `IPTVStore.replace_catalog` publishes the raw catalog. `IPTVProviderManager._catalog_committed` starts provider-local movie projection after the raw commit. Projection can fail independently of Live TV and Series sync. Their browsing and episode detail remain on the raw catalog path. `IPTVMovieService.start_projection` and the movie store expose progress, generation, and retry. [Sync and series detail](../../services/iptv_service.py) · [Projection wiring](../../services/iptv_provider_manager.py) · [Projection owner](../../services/iptv_movie_service.py)
- `IPTVWorkspace.playItem` selects a raw source when a movie has multiple IPTV versions. The playback POST calls `IPTVService.start_playback`, which keeps the upstream URL server-side and gives FFmpeg a tokenized loopback relay. FFmpeg emits a local HLS manifest that `IPTVPlayer` plays. The service tracks the token, process, and provider's TLS choice, and owns stop and cleanup. The player saves on-demand progress with provider-scoped `/history/<kind>/<item_id>`. The image route resolves a saved item and `cached_image` validates its stored URL. [Playback UI](../../src/features/iptv/IPTVPlayer.jsx) · [Workspace](../../src/features/iptv/IPTVWorkspace.jsx) · [Relay and cleanup](../../services/iptv_service.py) · [Playback and history routes](../../services/iptv_routes.py)

## Movie projection, first pass, and Unmatched

- `IPTVMovieStore.project_source_batch` records the provider source key and evidence. Provider View preserves separate playable sources. CP View groups accepted Film sources by verified TMDB identity within the provider. Manual match and removal persist in the provider's movie store. Accepted identities and manual locks survive refresh. Material provider listing changes can requeue an unlocked unresolved source, and claim checks prevent an obsolete in-flight worker result from overwriting the newer source. [Movie service](../../services/iptv_movie_service.py) · [Movie store](../../services/iptv_movie_store.py)
- `IPTVMovieService.start_enrichment` and `resume_enrichment` manage launch through the provider's worker and store. `enrich_source` classifies the listing, verifies a provider TMDB ID when supplied, then can fall through to the bounded title/year matcher. `bounded_search_candidates` skips individual candidate-detail 404s and continues checking remaining candidates. Missing required finalist details block that match. Optional localized metadata 404 leaves a verified identity intact. Authentication, throttling and transport errors stay in worker failure handling. `IPTVMovieStore.worker_control_status` reads summary and projection from one snapshot. Check the pending count, projection generation, and launch error before diagnosing missing work after a resync. [Worker control and matching](../../services/iptv_movie_service.py) · [Worker process](../../services/iptv_enrichment_worker.py) · [TMDB matcher](../../services/iptv_tmdb.py) · [Worker store](../../services/iptv_movie_store.py)
- `IPTVMovieStore._review_scope` builds the merged queue for `review_view=unmatched` with `review_scope=leftovers`. It includes settled no-match, uncertain identity, and settled unresolved category, filtered by availability and manual lock. Display and selection use the same predicate and support title, category, and playlist filters. `_validate_leftover_selection` rejects explicit stale selections. The older narrower review scopes remain available to existing callers. [Review requests and selection payload](../../src/features/iptv/IPTVWorkspace.jsx) · [Queue and selection owner](../../services/iptv_movie_store.py)

## ChatGPT matching and Apply

1. **Start and restore** · `IPTVWorkspace.metadataSelectionPayload` and `startBulkMetadata` send selected keys or the current filtered queue with an expected count. `ai_iptv_bulk_start` checks F5 readiness, evidence consent, provider projection and count, and freezes the selected keys and generation. Standard actions use the 5,000-source selection limit. The bulk resolver supports larger filtered scopes. `IPTVBulkMetadataJob` displays request allowance and progress. `useAIJob` restores the latest session for the account and provider and discards responses from a prior provider. Reconnecting reads status without replaying Start. [Bulk UI](../../src/features/iptv/IPTVBulkMetadataJob.jsx) · [Desktop job hook](../../src/features/ai/useAIJob.js) · [AI routes](../../services/ai_routes.py) · [Selection store](../../services/iptv_movie_store.py)
2. **Preparation and verification** · `IPTVJob._run_bulk` attempts local matching, then sends eligible unresolved titles in bounded batches for ChatGPT interpretation. Saved progress and request reservations support Continue. `IPTVMovieService.bulk_source_proposal` independently checks identity and evidence. An uncertain result stays in review. New jobs set `bulk_auto_apply` and omit the candidate-recovery protocol pin. Historical jobs with the pin retain the compatible recovery runner. [Bulk runner](../../services/chatgpt_iptv.py) · [Verifier](../../services/iptv_movie_service.py) · [Job store](../../services/ai_jobs.py)
3. **Writes and receipts** · `AIJobStore.claim_automatic_bulk_apply` schedules eligible new-job matches. Older eligible jobs can claim explicit job-wide Apply with scope, revision, expected count and request key. `run_bulk_apply` sends bounded chunks to `IPTVMovieService.apply_bulk_proposals`. The provider store checks current generation, source evidence and manual locks, and persists receipts with the match. If the process stops after the provider commit, reconciliation finds the existing receipt before advancing the AI checkpoint. Retrying a transient write can reuse verified proposals without another inference. Ordinary F4/F5 jobs use prepared reviews and explicit Apply. [Apply routes](../../services/ai_routes.py) · [Apply runner](../../services/chatgpt_iptv.py) · [Provider writes](../../services/iptv_movie_service.py) · [Receipt store](../../services/iptv_movie_store.py)
4. **Resume after provider sync** · `ai_job_continue` passes the provider's catalog readiness and eligibility reader to `AIJobStore.continue_job`. That transaction uses saved result IDs to exclude finished work, reconciles pending Apply receipts and stores the current execution generation and result cutoff. `bulk_work_sources` reconstructs the remaining ordered work from the original selection and cutoff. `IPTVEnrichmentPanel` renders the full preparation bar. [Continue route](../../services/ai_routes.py) · [Job store](../../services/ai_jobs.py) · [Provider store](../../services/iptv_movie_store.py) · [Progress panel](../../src/features/iptv/IPTVEnrichmentPanel.jsx)
5. **Saved TMDB search recheck** · `bounded_search_candidates` uses reported page counts, primary-year queries and bounded unfiltered rival evidence for current automatic Film matching. `ai_job_continue` uses the shared catalog refresh transaction before `AIJobStore.continue_job` freezes the search-limit proposals of a completed compatible job. This also works when an intervening sync has finished preparing a newer catalog. `IPTVJob._run_bulk` rechecks fresh source evidence with the saved hints, checkpoints the existing result and sends verified matches through normal Apply. [Matcher](../../services/iptv_tmdb.py) · [Job store](../../services/ai_jobs.py) · [Worker](../../services/chatgpt_iptv.py) · [Maintenance UI](../../src/features/iptv/IPTVBulkMetadataJob.jsx)
