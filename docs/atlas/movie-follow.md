## Entry points

| Action | Path and owner |
| --- | --- |
| Follow or unfollow | Home details, Discover, Movie Lists and AI Control cards, and the Home trailer player use `App.jsx::toggleFollow`. It sends POST or DELETE to `/api/user/followed-releases`. `user_followed_releases` validates the profile and enriches identity on POST, then calls `UserCurationStore.follow_movie` or `unfollow_movie`. The response carries the current rows and curation generation. [App](../../src/App.jsx) · [Shared cards](../../src/components/SharedMovieCards.jsx) · [AI result cards](../../src/features/ai-control/AIControlResult.jsx) · [Routes](../../app.py) · [Store](../../services/curation_store.py) |
| Start CP or press Scan | After the startup work gate, App reads the saved list, imports legacy browser follows if the server list is empty, then calls `executeFollowedOperation('full')`. Home Scan calls the same operation with a completion message. `POST /api/user/followed-releases/check` takes a nonblocking scan lock and calls `MovieAcquisition.check_followed`. The compatibility GET with `check=1` also scans. Ordinary GET loads the snapshot and can backfill dates. [App](../../src/App.jsx) · [Routes](../../app.py) · [Scan owner](../../services/movie_acquisition.py) |
| Import becomes ready or reconnect synchronizes the catalog | App listens for `CATALOG_READY_EVENT` with `catalog-ready` or `catalog-sync` and posts `/api/user/followed-releases/reconcile-owned`. `_reconcile_followed_release_ownership` uses committed Movie ownership. This operation can finish during a source scan. App queues another ownership pass if a second event arrives while it is busy. [App](../../src/App.jsx) · [Ownership route](../../app.py) · [Import and publication](movie-downloads-and-import.md) |

## Scan, data, and failure paths

1. `MovieAcquisition.check_followed` checks catalog ownership first. It skips a pending movie without verified IMDb identity and usually skips an already Available entry. A saved YTS release with known identity mismatch returns to the candidate path. `_followed_release_priority` orders candidates. Metadata dates help with ordering and presentation, while fresh scans consider pending films regardless of date or legacy retry time. [Scan owner](../../services/movie_acquisition.py) · [Identity, priority, and date helpers](../../app.py)
2. `_followed_release_search_context` selects enabled trusted Movie indexers. A trusted YTS indexer allows a bounded shared RSS pass. `_followed_rss_release` requires the YTS page to confirm IMDb identity, then unmatched rows go through the bounded parallel `_probe_followed_release` fallback. `_followed_release_candidate` and `MovieAcquisition.proper_release` enforce trusted indexer, movie scope, source, and HD quality. The Follow record keeps a profile ID, while scan availability uses these checks. `MovieAcquisition.review` resolves a profile for source review. [Scan and review owner](../../services/movie_acquisition.py) · [Provider and acceptance helpers](../../app.py)
3. `_followed_release_miss_patch` and `_followed_release_failure_patch` distinguish an unsuccessful completed search from provider failure. Scan results expose counters including `failed_searches`, `skipped.unverified_identity`, and `rss_matches`. A busy scan returns `scan_in_progress`. Failed provider or identity reads can be tried on a subsequent Scan. [Result projection](../../app.py) · [Scan owner](../../services/movie_acquisition.py)
4. `UserCurationStore` reads and writes the `followed_releases.json` document through `CatalogRepository` under the configured data root and flushes the export. `apply_followed_scan` merges by identity and the original `followed_at` to protect concurrent unfollow and re-follow. `followed_snapshot` pairs the current list with its generation. App rejects older list snapshots and deduplicates first-availability toasts for the surviving follow instance. [Store](../../services/curation_store.py) · [Catalog](../../services/catalog_repository.py) · [App](../../src/App.jsx)
