## Settings and data ownership

| Entry point | Owner and checks |
| --- | --- |
| **Settings → Library Locations** | `SettingsWorkspace` reads and saves `/api/config`. `app.py::set_config` validates and stores Movie roots, then makes the effective list available through `get_movies_dirs`. TV roots use `TVSettings` → `/api/tv/config` → `_tv_config`. Use the relevant domain's scan and path rules when a folder is missing. [Settings](../../src/features/settings/SettingsWorkspace.jsx) · [TV Settings](../../src/features/settings/TVSettings.jsx) · [App wiring](../../app.py) · [Movie scan](movie-library-and-identity-review.md) · [TV scan](tv-library-and-maintenance.md) |

A change of location points subsequent reads to owners resolved for the selected root. Consult the migration and backup tools for moving or restoring data. ## Startup, background work, and builds

- **App entry and frontend** · `app.py` registers Flask routes through `register_frontend_routes`. The frontend routes serve `dist/index.html` and `dist/assets`. Check the listener, served script name, checkout, and data owner independently when the UI differs from source. The test frontend can use `CP_TEST_DIST_DIR` contained in `CP_TEST_ROOT`. [App entry](../../app.py) · [Frontend route owner](../../services/frontend_routes.py) · [Windows launcher](../../run.bat)
- **Startup and refresh** · `_start_background_services` recovers pending ingestion, starts Library reconciliation and observation, launches `LibraryStartupCatchup`, and starts the awards and download monitors and TV workers. Startup catch-up compares persisted root state to pick changed directories. An unavailable root keeps its prior revision. The download monitor polls with an embedded-mode gate. TV scanning and Follow use separate workers. The Movie catalog event route exposes committed generation changes for browser refresh. [Startup wiring](../../app.py) · [Catch-up owner](../../services/library_startup_catchup.py) · [Download monitor](../../services/download_monitor.py) · [Catalog events](../../services/catalog_events.py)
- **Power actions** · The sidebar hands a request through the app and `src/api/power.js` to `/api/power/actions`. `PowerActionCoordinator.request` persists the action and any targeted jobs. `_job_checkpoint` distinguishes active work from journaled recovery, and `evaluate` checks readiness. Claim and completion records guard dispatch across restart. Status, cancel, and resume have separate routes. A request to close qBittorrent is restricted to CP shutdown in embedded mode. [App and routes](../../app.py) · [Frontend client](../../src/api/power.js) · [Coordinator](../../services/power_actions.py) · [Download states](movie-downloads-and-import.md)
- **Portable builds** · `tools/build_portable_release.py::build_release_zip` assembles the app, frontend, and pinned qBittorrent, FFmpeg, and native player runtimes. The private friend-test builder and launcher have their own setup and service data boundaries. Use the release packaging tests for contents and the friend-test tests for data-root relocation and launcher behavior. [Public and private build owners](../../tools/build_portable_release.py) · [Private launcher](../../tools/friend_test_launcher.py) · [Release packaging tests](../../tests/test_release_packaging.py) · [Friend-test packaging tests](../../tests/test_friend_test_package.py)
- **Help and support surfaces** · `HelpWorkspace` presents setup guidance and links to the relevant Settings sections. Check the corresponding Settings control and API for the effective configuration and test results. `Card Lab` and `Style Guide` are frontend routes for UI reference. [Help workspace](../../src/features/help/HelpWorkspace.jsx) · [Frontend route registration](../../services/frontend_routes.py)
